# Proto-Column Block Layout for Parse→Decode Pipeline

## Goal

Eliminate intermediate Go struct allocations during JSONL parsing by writing directly to ClickHouse-native proto column buffers.

## Current Path (Slow)

```
JSONL → jlexer → JSONLBlock/JSONLLog → []CustomLog → conversion → proto columns → ClickHouse
         [allocs]    [heap structs]        [heap slice]     [per-row work]
```

**Bottleneck**: `[]CustomLog` creates thousands of small heap structs per block, then we walk them again to fill proto columns for ClickHouse insert.

## Target Path (Fast)

```
JSONL → direct jlexer walk → proto columns → ClickHouse
         [precompiled]      [no intermediate]    [OnInput streaming]
```

**Win**: Zero intermediate allocations, single pass over JSON, columns are ClickHouse-ready.

## Block Structure

The `ProtoEventBlock` holds parsed events in columnar format, grouped by event type:

```go
type ProtoEventBlock struct {
    // Metadata (common to all events)
    BlockNumber    proto.ColUInt64
    BlockHash      proto.ColFixedStr  // 32 bytes
    BlockTimestamp proto.ColDateTime64
    
    // Per-event-type columns
    // Each event type has its own column set
    // Events of the same type share the same row index across that type's columns
    
    // ExchangeOrderFilled events
    Exchange_Maker           proto.ColFixedStr  // 20 bytes
    Exchange_Taker           proto.ColFixedStr  // 20 bytes
    Exchange_MakerAssetID    proto.ColUInt256
    Exchange_TakerAssetID    proto.ColUInt256
    Exchange_MakerAmount     proto.ColUInt256
    Exchange_TakerAmount     proto.ColUInt256
    Exchange_Fee             proto.ColUInt256
    
    // ConditionalTokens events
    CT_ConditionID          proto.ColFixedStr  // 32 bytes
    CT_OutcomeSlotCount     proto.ColUInt256
    CT_PayoutDenominator    proto.ColUInt256
    CT_Stakeholder          proto.ColFixedStr  // 20 bytes
    CT_CollateralToken      proto.ColFixedStr  // 20 bytes
    // ... etc
    
    // NegRisk events
    NRA_MarketID            proto.ColFixedStr  // 32 bytes
    NRA_Creator             proto.ColFixedStr  // 20 bytes
    // ... etc
}
```

## Access Pattern

Events are indexed by their type-specific row index:

```go
// Access ExchangeOrderFilled event at position i
maker := block.Exchange_Maker.Row(i)     // []byte slice into Buf, no alloc
makerAssetID := block.Exchange_MakerAssetID[i]  // proto.UInt256 value copy

// Add new event
block.Exchange_Maker.Append(addressBytes)
block.Exchange_MakerAssetID.Append(assetID)
```

## Integration Points

### 1. Parser Generation

Codegen generates `ParseBlockJSONLToProto(line []byte, block *ProtoEventBlock)` for each ABI:

```go
// Generated by codegen from ABI
func ParseBlockJSONLToProto(data []byte, block *ProtoEventBlock) error {
    lexer := &jlexer.Lexer{Data: data}
    lexer.Delim('{')
    
    for !lexer.IsDelim('}') {
        key := lexer.UnsafeFieldName(false)
        lexer.WantColon()
        switch key {
        case "header":
            // Parse block number, hash, timestamp
            // Directly into block.BlockNumber, block.BlockHash, etc.
        case "logs":
            // For each log:
            //   Decode address and topic0
            //   Route to appropriate event handler
            //   Handler writes directly to event-type columns
        }
        lexer.WantComma()
    }
    return lexer.Error()
}
```

### 3. ClickHouse Insert

Proto columns are already in ClickHouse format, use `OnInput` streaming:

```go
input := proto.Input{
    {Name: "maker", Data: &block.Exchange_Maker},
    {Name: "makerAssetId", Data: &block.Exchange_MakerAssetID},
    // ...
}

err := conn.Do(ctx, conn.OnInput(input, func(ctx context.Context) error {
    // Stream all rows in one query
    return nil
}))
```

## Memory Layout

**Column buffers** are contiguous byte slices:
- `proto.ColFixedStr`: Single `[]byte` with fixed-width entries
- `proto.ColUInt256`: `[]proto.UInt256` (4×uint64 per row)
- `proto.ColDateTime64`: `[]time.Time`

**No row objects**: Each event is represented by its index across columns. The processor iterates by index and accesses all needed fields by column lookup.

## Arena Allocator

For variable-length arrays (e.g., `payoutNumerators[]` in ConditionResolution), use an arena/bump allocator:

```go
type Arena struct {
    chunks [][]byte
    offset int
}

func (a *Arena) AllocateBytes(n int) []byte {
    // Bump allocate from current chunk
    // Move to new chunk when current fills
}

func (a *Arena) Reset() {
    // Keep one chunk, discard rest
    a.offset = 0
}
```

The arena holds variable-length data. Proto columns with fixed-width data (addresses, hashes, uint256) don't need the arena.

## Benefits

1. **Zero intermediate allocations**: Parser writes directly to final column format
2. **Single JSON pass**: No decode → struct → encode roundtrip
3. **ClickHouse-native**: No conversion before insert
4. **Cache-friendly**: Columnar access patterns
5. **GC-friendly**: Fewer heap objects, less scan work
